## 2. 状态与生命周期结构

### 2.1 UI 状态

`OpenAIDeviceLoginState` 包含：

- `Idle`
- `RequestingCode`
- `WaitingForUser`
- `ExchangingToken`
- `Authenticated`
- `Cancelled`
- `Expired`
- `Unsupported`
- `NetworkError`
- `AuthFailed`

UI 状态只包含 attempt ID、用户必须看到的原样 user code、登录网址和脱敏错误分类。
设备授权 ID、authorization code、PKCE 和 Token 均不进入 StateFlow。
`WaitingForUser.toString()` 明确遮蔽 user code。

### 2.2 路由级 ViewModel

`OpenAIDeviceLoginViewModel` 使用 `viewModelScope` 持有协调器：

- Compose 重组和 StateFlow 重新订阅不会启动新请求；
- Phase 4 从 `ADD_PROVIDER` 的 NavBackStackEntry 取得 ViewModel 后，旋转和
  Activity 重建可复用同一任务；
- ViewModel 不使用 `SavedStateHandle`、Bundle、数据库或配置文件保存临时秘密；
- 系统杀死进程后会创建新 ViewModel，并从 `Idle` 重新开始；
- `onCleared()` 调用协调器 `close()`，使全部旧 generation 和 Token 租约失效；
- ViewModel 目前只向 UI 暴露状态、开始和取消，不暴露 Token 或提交租约。

真实 Android 旋转、后台、锁屏和进程回收仍需 Phase 6 真机验收。

## 3. 协调与重试

### 3.1 单一有效尝试

- `start()` 只在 Idle 或终止状态创建新 generation；
- Requesting、Waiting、Exchanging 或 Authenticated 时连续调用返回 false；
- `cancel()` 先推进 generation、清空敏感引用并切换为 Cancelled，再取消 Job；
- `close()` 永久关闭协调器，后续 `start()` 返回 false；
- 每个请求返回、状态更新、Token 交换和提交租约都再次校验 generation。

即使测试 fake 在 `NonCancellable` 中故意忽略取消并迟到返回，旧请求也不能轮询、
交换 Token、覆盖新状态或产生可提交凭据。

### 3.2 轮询与总超时

- 得到用户码后首次轮询立即发生；
- Pending 后按服务端 interval 等待；
- interval 秒转毫秒采用饱和计算，超大值不会溢出；
- 15 分钟只约束轮询阶段；
- 轮询超时后进入 Expired，并允许新尝试；
- 已经在 15 分钟边界触发超时但仍在 NonCancellable 中迟到返回的 Authorized
  结果仍会被丢弃；
- Token 交换发生在成功轮询之后，不会因刚好接近轮询截止时间而被误丢弃。

### 3.3 有限网络重试

默认策略：

- 用户码请求最多 3 次；
- 用户码网络失败后退避 1 秒、2 秒；
- 轮询连续网络失败最多 3 次；
- Pending 会重置连续网络失败计数；
- 轮询重试等待取服务端 interval 与指数退避的较大值；
- 退避默认从 1 秒增长，最大 8 秒；
- 连续失败进入带准确阶段的 `NetworkError`，不永久加载；
- HTTP 或协议错误不重试，进入准确阶段的 `AuthFailed`；
- Token 交换网络失败不自动重试，避免重放可能已被消费的一次性授权码。

协议实现意外抛出的非取消 Exception 会转换为不含异常 message 的 `Internal`
安全终态；`CancellationException` 始终原样传播。

## 4. Token 响应时间与提交租约

### 4.1 固化真实过期时刻

Phase 2 原实现保存 `expires_in`，准备在用户点击保存时计算 `expire_at`。Phase 3
审查发现：登录成功后若用户等待数分钟再保存，这会错误延长 Token 有效期。

现已修正：

- `OpenAIDeviceAuthClient` 注入 epoch clock；
- Token HTTP 响应解析成功时立即固化 `expiresAtEpochMillis`；
- `toOAuthStorageJson()` 不再接收保存时的当前时间；
- 过期时间加法继续使用饱和保护；
- 有 expiry 时强制要求绝对过期时刻同时存在；
- 测试证明保存 JSON 使用响应到达时计算的值。

### 4.2 一次性提交租约

协调器成功后私有保存 Token，UI 状态只显示 Authenticated。Phase 4 内部提交流程可：

1. 以当前 attempt ID 一次性领取 `OpenAIDeviceTokenLease`；
2. 每个可中断写入阶段前调用 `tokensIfValid()`；
3. 取消、离页、ViewModel 销毁或新 generation 会使租约立即失效；
4. Provider 与加密凭据都成功后调用 `completeTokenCommit()`；
5. 最终握手返回 false、任一步异常或取消时，按 pending-commit 标记补偿清理。

领取租约不会提前推进 generation，因此 Activity 重建不会出现“仍是 Authenticated，
但 Token 已被 UI 提走且不可复核”的死状态。ViewModel 当前不公开租约，Phase 4 必须
把整个提交 Job 和租约封装在 `viewModelScope` 内，Compose 只调用“保存 Provider”。
